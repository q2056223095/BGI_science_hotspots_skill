# Validation System / 验证体系

本目录用于回答一个核心问题：

> 新版本是否真的比旧版本更好，而不是只是规则写得更多？

## 1. 冻结基线

本轮验证冻结两个不可随意移动的比较基线：

- `baseline/v0.4.0` -> `8ba25cd5f44f723e0b23e4581209c6204e1ab849`
- `baseline/v0.5.1` -> `602c1d9766cb18d22b80764d0cd75fcf581248b7`

验证开发分支：

- `validation/regression-v1`

基线分支只用于复现和比较。后续规则修改不得直接改写基线。

## 2. 第一轮验证目标

第一轮先验证“文案与科学边界层”，同时加入一条图片状态机协议测试。

覆盖四类真实热点：

1. 机制型：燕麦苗期抗旱基因组研究
2. 发现型：冥王星表面近期液氮活动证据
3. 技术型：北极 zero curtain 与 GeoCryoAI 制图
4. 争议/反常识型：长寿哺乳动物癌症相关位点的保守性

另加：

5. 图片执行协议：`开始做图` / `继续生成图4-图5` 时是否仍保持单页状态机

真实 Case 见 `tests/regression/manifest.json`。

## 3. 回测方法

同一 Case 对两个冻结版本使用：

- 同一份原始来源包
- 同一用户任务
- 同一目标平台
- 不给某个版本额外信息
- 不用另一个版本的规则手工补丁

第一轮采用 **same-model controlled replay（同模型受控重放）**：在同一模型条件下分别按 0.4.0 和 0.5.1 规则完成一次输出，再按同一 Rubric 评分。

这不是统计学 benchmark。它的作用是先建立可复现的测试资产、失败模式和评分门槛。后续应增加多次采样、不同模型和自动 runner。

## 4. 100 分 Rubric

| 维度 | 分值 | 判断重点 |
|---|---:|---|
| 事实准确与归属 | 15 | 数字、对象、期刊、时间、动作是否准确；自述/推断是否混写 |
| 材料充分与证据推进 | 15 | 是否有至少 3 条独立材料；段落是否新增信息 |
| 科学边界 | 15 | 样本、条件、研究阶段、外推限制是否放在影响判断的位置 |
| 过度外推控制 | 10 | 是否从机制跳到生活建议、商业应用、宏大意义 |
| 信息密度与段落推进 | 10 | 是否重复解释、固定模板打卡、注水 |
| 中文自然度与编辑感 | 10 | 是否存在翻案腔、假深刻、假读者、报告腔、整齐排比 |
| 标题准确性 | 5 | 抓人但不夸大，不把“证据”写成“已经发生” |
| 平台适配 | 5 | 小红书可读性、篇幅、节奏是否自然 |
| 来源透明度 | 5 | 是否保留关键来源和事实身份 |
| 视觉/后续任务可执行性 | 10 | 轮播任务是否清楚；实际出图是否遵守状态机 |
| **总分** | **100** | |

## 5. 发布门槛

一个候选版本进入 main 前，至少满足：

- 平均分 >= 88
- 任一真实 Case 不得低于 82
- `事实准确与归属` >= 13/15
- `科学边界` >= 13/15
- 不得出现 Critical Failure

Critical Failure 包括：

- 编造论文、机构、数字、人物原话或用户亲历
- 把动物/体外/机制结果直接写成人体建议
- 把预测/回溯测试写成已经投入实际应用
- 把“证据提示/可能”写成确定发生
- 未经依据把局部结果写成“彻底推翻”
- 实际出图把多页拼进一个画布

## 6. 版本提升判定

候选版本相对基线只有在下面至少一个条件成立时，才算真实提升：

1. 总分平均提升 >= 5 分，且无核心维度退步；
2. 修复一个 Critical Failure；
3. 针对已知生产故障形成可复现的防回归测试。

如果只是 README、措辞或规则数量增加，但回测没有改善，不计为能力升级。

## 7. Regression Case 设计原则

每个 Case 必须包含：

- `id`
- `type`
- `title`
- `user_task`
- 至少一个一手/权威来源
- `source_facts`
- `expected_behaviors`
- `failure_traps`

Case 不应只测试“能不能写好”，而要主动埋入容易出错的传播陷阱。

例如：

- `evidence` vs `proof`
- `association` vs `causation`
- `backtest` vs `operational deployment`
- `one study` vs `general rule`
- `planning 5 pages` vs `generating 5 pages in one canvas`

## 8. 运行结构检查

```bash
python scripts/check_regression_suite.py
```

该脚本只检查测试资产结构与必填字段，不替代真实 LLM 回测和人工科学审阅。

## 9. 后续迭代

第二轮建议加入：

- 健康/医学高风险 Case
- 新闻二手报道与论文原文冲突 Case
- 只有弱来源、必须降级措辞的 Case
- 用户要求强标题党的对抗 Case
- 真实图片生成结果的逐页视觉一致性评分
- 3 次以上随机采样，记录均值和方差
- GPT / Claude / Gemini 等跨模型对照
